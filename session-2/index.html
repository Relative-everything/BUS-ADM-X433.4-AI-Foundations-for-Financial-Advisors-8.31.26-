01 · Mechanism9 min

Next-Token Probabilities for a Single Prompt

Wolfram's description of the mechanism is one sentence long: the model asks, over and over, “given the text so far, what should the next word be?” and each time adds a word. There is no separate step where it checks whether the sentence is true.

Take his example prompt. At each position the model produces a ranked list of candidate continuations with probabilities attached. Click a bar to select that continuation and watch the distribution recompute for the next position. Try running it twice: once always taking the top bar, once taking the second or third.

Prompt
Probability of the nth-ranked candidate token, first position
Wolfram reports that the fall-off across ranked candidates follows an n⁻¹ power law — the straight line on a log-log plot that he notes is characteristic of the general statistics of language. Rank 1 holds a large share; by rank 20 the candidates are individually negligible but collectively substantial.
Source: Wolfram, S. (2023), “It's Just Adding One Word at a Time.” Curve shape is as reported (n⁻¹ decay) H. Individual token labels above are illustrative, not extracted from the published figure L.

What this rules out

A planner reading an AI answer to a tax question is not reading a lookup result. They are reading a sequence in which each word was chosen because it was a probable continuation of the words before it. A correct citation and a fabricated citation are both probable continuations. Nothing in the mechanism distinguishes them.

02 · Foundation6 min

Laplace on Probability as a Measure of Ignorance

In 1814 Laplace proposed an intellect that knew every force and every position in nature. For such an intellect, he wrote, nothing would be uncertain; the future, like the past, would be present to its eyes. Probability, on his account, is not a property of the world. It is a property of the observer's incomplete information.

That distinction is the whole session. A client's 2025 return either does or does not permit a particular treatment. There is a fact. When the model gives you a probability distribution over answers, it is not reporting uncertainty in the tax code. It is reporting uncertainty about which continuation a human writer would have produced. Those are different objects, and the second one is not evidence about the first.

Two objects, side by side

Confidence in the output is not evidence about the world. It is evidence about the training data.

The practical consequence

Laplace's framing gives you the verification rule for the rest of the course. If probability is a statement about what the observer does not know, then reducing your own ignorance — opening the Code section, pulling the actual return, checking the effective date — is the only operation that changes the answer's reliability. Asking the model again, asking it more confidently, or asking it to double-check itself does not. Those operations resample the same distribution.

03 · Mechanism9 min

Temperature and Output Variance

Commit before the content runs

You send an identical prompt to the same model twice, an hour apart, with no other change. Which is true?

If the model always picked the top-ranked candidate, Wolfram notes, you get flat text that sometimes repeats word for word. Picking lower-ranked candidates sometimes produces more interesting text. The parameter governing how often that happens is called temperature, and Wolfram is explicit that there is no theory behind the value — 0.8 is simply what has been found to work for essays.

The slider below applies the actual transformation: each candidate's probability is raised to the power 1/T and the set is renormalised. Low T sharpens the distribution toward the leader. High T flattens it. Then the panel samples the same prompt five independent times so you can see the spread.

Temperature
0.0 — deterministic0.8 — Wolfram's essay setting1.5 — degraded

Three consequences for an advisory practice

Consequence 01

The prompt is not the record

At any temperature above zero the same prompt produces different text. An audit trail that stores only the prompt has stored the input to a random process, not the output you relied on.

Consequence 02

Re-asking is not verification

Running the query again draws a second sample from the same distribution. Agreement between two samples is evidence about the distribution's shape, not about the tax code.

Consequence 03

Consumer chat tools do not expose T

You cannot set temperature in most subscription interfaces. You control variance through the prompt — by constraining the output space — not through a setting.

04 · Failure mode6 min

Sampling Failure on a Task That Requires Counting

Wolfram trained a small transformer on a language with exactly one rule: parentheses must balance. The rule is simpler than any tax provision. The network still fails, and it fails in a specific and instructive way.

After roughly 400,000 trained weights, he reports, the network assigns about a 15 percent probability to a closing parenthesis in a position where closing would necessarily leave the sequence unbalanced. It is not confused about the rule in general. It is unable to hold a running count, because a feed-forward pass has no loop in which to keep one. He notes that even the full production model has a hard time matching parentheses in long sequences.

Extend the sequence — click a token to append it
Open count is tracked below the predictor, not by it.
Two kinds of task, one architecture
Tasks a human solves at a glance are the ones the network handles. Tasks requiring an explicit procedure carried across steps are the ones it approximates and then drops.
Source: Wolfram, S. (2023), “What Really Lets ChatGPT Work?” and the parenthesis-language section. Characterisation as reported H.

The mapping to your work

Confirming that a cited authority exists is a lookup against an index. Confirming that it says what the sentence claims is a comparison against a text. Confirming that it still says that is a check against an effective date. None of the three is a continuation task, and the architecture that writes the sentence is not the architecture that performs any of them. This is why grounding, retrieval, and your own eyes on the source are separate additions and not properties the model has.

The model is not bad at counting because it is undertrained. It is bad at counting because counting is not what it does.

What the evidence says about Persona

Zheng and colleagues tested 162 distinct roles across four model families on 2,410 factual questions. Adding a persona to the system prompt did not improve accuracy against a no-persona control. The best-performing role varied question by question, and automated strategies for choosing a good role performed no better than picking one at random.

Effect of adding a persona to the system prompt on factual accuracy
Persona changes register, vocabulary and audience calibration. On objective questions with a checkable answer, it does not reliably change whether the answer is right.
Source: Zheng, M., Pei, J., Logeswaran, L., et al. (2024). When “A Helpful Assistant” Is Not Really Helpful: Personas in System Prompts Do Not Improve Performances of Large Language Models. Findings of EMNLP 2024. Study design and null result as reported H.

Where the effort should go instead

ComponentWhat it controlsEffect on whether the answer is correct
PersonaRegister, vocabulary, assumed audienceNo reliable effect on objective accuracy
TaskWhich operation gets performedLarge — a wrong verb produces a competent answer to a different question
ContextThe facts available and the boundary on sourcesLargest — this is the only channel through which the model can see your client's situation
FormatThe shape of the outputLarge — a constrained output space is checkable; free prose is not

Persona still earns a place in a template. It sets the reading level for a client-facing email and the terseness for an internal case note, and those matter. It is simply not the lever for correctness, and a template whose only specification is an elaborate persona is an unspecified template.

A related result on prompt length

Anthropic reports removing more than 80 percent of Claude Code's system prompt for its two most recent models without a measurable loss on its coding evaluations.M Longer prompts are not better prompts. Specific prompts are better prompts, and specificity is usually shorter than the padding it replaces.

07 · Diagnostic8 min

Prompt Specification Triage

Three categories, not two. A prompt can be underspecified. It can be fully specified and still produce output nobody can check. Or it can be specified in a way that makes checking possible. Only the third is usable in a fiduciary practice.

Category A

Underspecified

The output shape, the source boundary, or the operation itself is left to the model to choose.

Category B

Specified, unverifiable

You know exactly what will come back. You have no procedure for confirming it is right.

Category C

Specified and verifiable

The output is constrained to a form where a named source settles whether each element is correct.

Several of these are designed to be mis-sorted. Read the whole prompt before choosing.

08 · Technique9 min

Wolfram makes an observation that most prompting advice skips: you can tell the model something once, as part of the prompt, and it will use it. The prompt is not a request. It is the entire evidentiary record available to the model at the moment it answers.

Which means the standard of inquiry you apply to a prompt is the same standard you apply to a client interview. You would not build a recommendation from a client meeting in which you asked one question. Why steps 2 and 4 sit apart

Step 2 is the elicitation of what a client actually wants, which is frequently not what they first say they want. Step 4 is the exercise of professional judgment that your registration, your credential and your liability all attach to. A model can draft language for either. It cannot perform either, and a workflow that quietly lets it is the failure mode this course exists to prevent.

Steps 3 and 7 are the opposite case. Analysing alternative courses of action and monitoring for drift are both high-volume, structured, and verifiable against a source. They are where the measurable time recovery lives.

Four failure types, in ascending order of danger

The Stanford taxonomy separates fabrication from misgrounding. This transaction adds a third and a fourth that matter specifically in estate planning, because the technique’s most-cited authorities include two cases that were never decided.

Type 01

Fabrication

The authority does not exist. Fails an existence search in fifteen seconds. The least dangerous failure, because it is the only one that is trivially catchable.

Type 02

Misgrounding

Real, retrievable, correctly formatted, and does not support the proposition attached to it. Requires reading the authority.

Type 03

Superseded

Correct when issued, changed since. Training data has a cutoff; the Code does not.

Type 04

Cited as holding, never decided

A real docket number, real parties, a real dispute — and a stipulated decision rather than an opinion. Nothing was held. The citation is genuine and the proposition has no support behind it. Neither an existence check nor a text check catches this one.

Citation triage — classify each

Six items an AI assistant returned when asked what authority supports the Cole IDGT sale. Classify each. All six are exercise material. Do not carry any classification into practice without checking the authority yourself, which is the entire point.

The verification order

Four checks, and they must run in this sequence, because each one is only meaningful if the previous one passed.

Check 01 — Existence

Does the authority exist

Section number, revenue procedure number, case reporter and page. A search against the Code or the reporter settles it. Fifteen seconds.

Check 02 — Text

Does it say what the sentence claims

Open it and read the operative language. This is the check that catches misgrounding and the one most often skipped.

Check 03 — Currency

Is it still operative

Amended, superseded, modified by a later revenue procedure, or subject to a sunset. Training data has a cutoff; the Code does not.

Check 04 — Applicability

Does it reach these facts

The provision is real, correctly stated and current, and governs a different fact pattern from your client's. Only you can perform this one.

Existence is the floor of verification and never the ceiling.

What Session 3 does that this session could not

Everything in this file has treated the model as a closed system. You improved the output by improving the prompt, because the prompt was the only channel available. Section 8 made that explicit: the model cannot see the Cole file, so what you type is the entire evidentiary record.

Session 3 opens that channel. Grounding lets the model read the actual documents — the 2011 wills, the 2014 buy-sell, the 2023 appraisal, the unexecuted trust instrument — and cite the passages it used. That solves the problem this session could only work around, and it introduces a failure this session could not produce: an answer that is fully sourced, correctly attributed to a real document in your own corpus, and materially wrong, because the passage retrieved was the nearest one rather than the right one.

The Cole document set is the corpus. The question that follows you into it is the one section 10 left open: does a 2023 appraisal still support a 31% discount, and which document in the folder actually says so.
